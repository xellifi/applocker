# AppLocker Business Operations Manual

Welcome to the AppLocker Administrative Guide. This document provides step-by-step instructions for business owners to distribute the app, manage permissions, and push "Over-The-Air" (OTA) updates to clients dynamically.

---

## 🏗️ 1. Pushing Over-The-Air (OTA) Updates
Your child APK is now designed to automatically check for updates every time it opens. When you have a new version ready, follow this process to cleanly push it to all users:

### Step 1: Update the Code Version
1. Open your code editor and find `pubspec.yaml`.
2. Locate the line: `version: 1.0.7+7` (for example).
3. Change it to the new version. **Important:** You must increment the number after the `+`. Example: `version: 1.0.8+8`.

### Step 2: Compile the Production APK
Run this standard build command in your terminal:
```bash
flutter build apk --release --target lib/child/main_child.dart --dart-define=APP_MODE=child
```
Upload the resulting `app-release.apk` file to your server or Google Drive, making sure the direct download link is publicly accessible.

### Step 3: Trigger the Update via Firestore
1. Open your **Firebase Console**.
2. Go to **Firestore Database**.
3. Create a collection named `config` (if it doesn't exist).
4. Inside `config`, create a document named `appUpdates`.
5. Add the following fields exactly as written:
   - **`latestBuild`** (Number): `8` (This must match the number after the `+` in your pubspec.yaml).
   - **`latestVersion`** (String): `"1.0.8"`
   - **`updateLogs`** (String): `"Added new features and fixed bugs."`
   - **`downloadUrl`** (String): `"https://your-website.com/direct-download-link.apk"`

Whenever a child's phone opens the app, it will hit Firestore. If their local build number is less than `8`, a pop-up dialog will appear on their screen telling them to update, providing your custom release notes and the download button!

## 📦 2. Distributing the App to Clients
You have two distinct methods to distribute this app based on how tech-savvy your clients are. Your single compiled APK seamlessly adapts to both!

### Method A: The "Non-Techy" Consumer (Recommended)
This is the standard distribution approach for general parents.
1. Host your `app-release.apk` on a website.
2. The parent downloads it on the child's phone and taps 'Install'.
3. **Capabilities:** The parent has full UI access, screen locking, schedules, and analytics. If the parent chooses to "Hide" an app on the dashboard, the app does not mathematically vanish from the launcher, but will immediately display the un-bypassable lock screen if the child taps on it. 

### Method B: The "Fully Managed" Setup (Hiding Icons Physically)
If you require icons to dynamically disappear entirely from the phone launcher, Android requires **Device Owner** / **Profile Owner** privileges. This is an advanced deployment step.
1. Factory reset the target child's phone.
2. Complete setup without adding any accounts.
3. Plug the phone into a PC with ADB installed.
4. Install the app via: `adb install -r path/to/app-release.apk`.
5. Run the privilege command: 
   `adb shell dpm set-profile-owner com.parentalcontrol.applocker/.AppLockerAdminReceiver`
6. Unplug the phone and sign into Google normally.
7. **Capabilities:** Unrestricted control. When the parent hits "Hide", the physical icon completely drops off the phone interface.
